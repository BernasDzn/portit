# Definition of Ready (DoR)

## Purpose
This document defines the criteria that must be met before a User Story can be considered ready for development and included in a sprint. 

## Criteria Checklist

### 1. Clear Description & Acceptance Criteria
- [ ] Description clearly states "As a [role], I want [feature], so that [benefit]"
- [ ] Acceptance Criteria are specific, measurable, and testable
- [ ] All ACs are aligned with project specifications and client clarifications

### 2. Business Value Defined
- [ ] Business value is clearly stated and justified

### 3. Technical Dependencies Identified
- [ ] All dependencies on other stories/features are documented

### 4. Data Model Considerations
- [ ] Required entities and relationships are identified
- [ ] Data validation rules are documented
- [ ] Persistence requirements are clear

### 5. Non-functional Requirements
- [ ] Compliance needs (RGPD, etc.) are addressed
- [ ] Refer to `LEI-2025-26-Sem5-Project_v1-SystemDescription`'s "3.3 Other Requirements" for other requirements

### 6. Team Understanding
- [ ] Story has been discussed and understood by all team members
- [ ] Development team has provided estimates
